# Task Tracker Alert Export Contract

This export path is currently disabled in the TASK-first app. The contract is preserved for future reference if the user re-enables a LifeSync-to-Task-Tracker inbox handoff.

When enabled, LifeSync can queue alert requests for another app to import later. LifeSync does not edit Task Tracker data, does not depend on Task Tracker internals, and does not expect a useful result from the inbox write.

## Runtime File

Default path:

```text
<LifeSync build output>\data\task-tracker-alert-requests.json
```

The path is configurable in LifeSync `config.json`.

## Shape

```json
{
  "schemaVersion": 1,
  "createdAt": "2026-05-20T10:30:00+08:00",
  "sourceApp": "LifeSync",
  "requests": []
}
```

Each request:

- `requestId`: unique request write id.
- `sourceKey`: stable duplicate key generated by LifeSync.
- `sourceKind`: `task`, `track-low-stock`, `track-expiry`, or `track-replacement`.
- `title`: suggested Task Tracker task title.
- `remark`: detailed alert summary.
- `eligibleAt`: when LifeSync considers this alert ready to export.
- `scheduledAt`: suggested Task Tracker scheduled datetime.
- `notificationRules`: Task Tracker-style notification rule array.
- `priority`: suggested priority: `none`, `medium`, `high`, or `urgent`.
- `metadata`: non-identity details for importers and troubleshooting.

The task creation fields intentionally follow Task Tracker's expected task style:

```json
{
  "title": "Task title",
  "remark": "Optional remark",
  "scheduledAt": "2026-05-20T21:00:00+08:00",
  "notificationRules": [
    {
      "type": "specificTime",
      "specificAt": "2026-05-20T20:30:00+08:00"
    }
  ]
}
```

## Source Key Rules

- TASK source keys do not use Google Sheet row number because row numbers can change after sheet insert/delete.
- TASK source keys are short hashes of normalized category, type, task title, warning date, expired date, and alert kind.
- TASK row number is exported only as metadata.
- TRACK source keys use the stable track item id plus alert kind and the relevant batch/date/status detail.

## Scheduling Rules

- TASK warning date different from expired date: export becomes eligible on warning date, scheduled/notification date is expired date.
- TASK without separate warning date: eligible date is expired date.
- TRACK low/out stock: eligible immediately, scheduled date is now, notification rules are empty.
- TRACK expiry: eligible when LifeSync expiry alert is active, scheduled/notification date is expiry date.
- TRACK replacement: eligible when due/overdue, scheduled/notification date is next replacement date.

## Duplicate Expectations

LifeSync stores exported source keys in `config.json` and will not write the same source key again, even if the app restarts or the timer checks the same alert later. If the export inbox already contains the same `sourceKey`, LifeSync treats it as already queued and records that key in `config.json` too.

Importers should still treat `sourceKey` as idempotent, because users may manually copy files, restore backups, or clear LifeSync config.
